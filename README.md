# 久慈川 額田 水位ビューア

GitHub Pages にそのまま配置できる静的Webアプリです。

## 構成
- `index.html`
- `style.css`
- `app.js`
- `config/stations.json`
- `assets/`（アイコン等）
- `site.webmanifest`

水位データはこのリポジトリには含まれません。ビューア（`app.js`）は [`kuji-waterlevel-data`](https://github.com/tanyeee/kuji-waterlevel-data) が公開するJSONをブラウザから直接読み込んで表示します。

## GitHub Pages での公開手順
1. GitHubで新しいリポジトリを作成
2. このフォルダ内のファイルをそのままアップロード
3. リポジトリの `Settings` → `Pages` を開く
4. `Deploy from a branch` を選択
5. `main` ブランチの `/root` を指定して保存
6. 数分後に公開URLが発行されます

## 仕様メモ
- 初期表示は1年分です
- 欠測 `$`、閉局 `#`、未登録 `-` は欠損として扱っています
- `*` は暫定値として有効値扱いです
- 増水判定は A/B 切替式です
  - A: 直近3年基準
  - B: 直近7日平均との差


## データの取得・更新

水位データの取得・保存・定期更新は、データリポジトリ [`kuji-waterlevel-data`](https://github.com/tanyeee/kuji-waterlevel-data) に移行しています。取得処理は同リポジトリの `fetcher/`、定期実行は Cloudflare Worker が担当します。時刻水位月表からの取得、直近10分データの取得、手動更新の手順など取得処理の詳細は `kuji-waterlevel-data` 側のドキュメントを参照してください。

このビューア自身はデータの取得・保存を行いません。長期1時間データは `kuji-waterlevel-data` の `data/manifest.json` と地点・年別JSONから、直近データも同リポジトリが公開するJSONから読み込みます。外部データを取得できない場合はこのリポジトリ内へのフォールバックはせず、既存のエラー表示・空表示になります。

## 地点追加

新しい地点を追加するには、このビューアの `config/stations.json` と、データリポジトリ [`kuji-waterlevel-data`](https://github.com/tanyeee/kuji-waterlevel-data) の `fetcher/config/stations.json` の両方を更新する必要があります。取得ID（`hourly.station_id` / `ten_min.station_id` / `ten_min.ofc_cd` ・ `itmknd_cd` ・ `obs_cd` / `kawabou.*` など）の意味や取得方法の詳細は `kuji-waterlevel-data` 側を参照してください。

このビューア側で画面表示に関わる主なフィールドは次のとおりです。

- `id`: URLや `kuji-waterlevel-data` 側のアーカイブパスに使う英数字のID。データリポジトリ側と一致させる必要があります
- `name` / `selector_name` / `observation_name`: 画面表示名・セレクト表示名・観測所名
- `river_id` / `river_name`: 河川別グループ分けに使う分類
- `display_groups`: Webアプリの観測地点セレクトに表示する河川名と地点ID。ここにない地点も定義は残せますが、選択肢には表示されません
- `flood_levels` / `flood_levels_basis`: 防災基準水位（後述）
- `level_zones`: 地点固有の浸水目安など（後述）
- `reference_stats_enabled`: `false` にすると直近3年基準線・水位判定を「データ蓄積中」として無効化します

将来、河川を増やす場合は `rivers` に河川を追加し、各地点の `river_id` を対応する河川IDへ向けます。

現在のWebアプリ表示対象:

- 久慈川: 富岡橋、幸久橋（額田）、榊橋上（川の防災情報）
- 里川: 機初
- 山田川: 常井橋
- 涸沼川: 高橋、下石崎（川の防災情報）
- 那珂川: 那珂川大橋

### 川の防災情報にのみ掲載される地点

榊橋上・高橋・下石崎は、水文水質データベースではなく「川の防災情報」が画面表示に使用する公開JSONから取得しています（取得処理は `kuji-waterlevel-data` の `fetcher/` を参照）。この3地点は追加以前の長期履歴がないため、直近3年の基準線と水位判定を「データ蓄積中」として無効化します。実測グラフと選択期間の最低・平均・最高は表示します。

下石崎は、現地で確認された護岸浸水の目安として1.90 mに「護岸浸水目安」を表示し、それ以上の範囲を網掛けします。これは国土交通省の防災基準水位とは別の地点固有情報です。

### 防災基準水位

公式基準がある地点は、国土交通省 常陸河川国道事務所の「久慈川・那珂川基準水位」（令和2年6月1日適用）に基づいています。額田だけは下記の過去データによる参考換算です。画面上の富岡橋は公表表の「富岡」、那珂川大橋は「野口」に対応します。

| 画面上の地点 | 氾濫注意水位 | 避難判断水位 | 氾濫危険水位 | 氾濫発生水位 |
| --- | ---: | ---: | ---: | ---: |
| 富岡橋 | 2.50 m | 2.90 m | 3.50 m | 4.60 m |
| 幸久橋（額田）※参考換算 | 4.80 m | 5.30 m | 5.90 m | 7.10 m |
| 機初 | 3.00 m | 3.00 m | 3.10 m | 3.80 m |
| 常井橋 | 3.00 m | 3.50 m | 3.80 m | 4.30 m |
| 那珂川大橋 | 3.50 m | 4.10 m | 4.50 m | 5.80 m |

従来3区分の出典: <https://www.ktr.mlit.go.jp/hitachi/hitachi00094.html>

令和8年追加の氾濫発生水位の出典: <https://www.mlit.go.jp/river/bousai/main/saigai/tisiki/syozaiti/pdf/suibou_kunikannrikouzuiyohou_0529.pdf>、<https://www.mlit.go.jp/river/bousai/main/saigai/tisiki/syozaiti/pdf/suibou_kunikannrisuiisyuuchi_0529.pdf>

従来の「警戒水位」は現在の「氾濫注意水位」に相当します。防災基準線は初期状態ではオフとし、表示すると基準線を含む高さまでグラフの縦軸を広げます。

額田には公式の防災基準水位がありません。画面では2016年1月〜2026年9月の富岡橋・額田の1時間値から、富岡橋ピークが0.5 m以上となった増水18事例を抽出し、ピーク同士の回帰式 `額田 = 1.107 × 富岡橋 + 2.049 m` で富岡橋の公式4基準を換算しています。相関係数は0.984、回帰のRMSEは0.24 m、ピークの主な到達差は2〜4時間でした。値は0.1 m単位に丸めています。これは額田の公式基準ではないため、グラフと統計欄では「参考換算」と明記します。

画面では1つの観測地点セレクトに河川名のグループ見出しを付けます。潮汐の影響を受ける地点は選択肢から除外しますが、潮汐アプリなどが利用できるよう、`kuji-waterlevel-data` 側ではデータの取得・保存を全地点で継続します。

支流の機初（`303011283322080`、里川）と常井橋（`303011283322070`、山田川）も2016年以降の1時間履歴と直近10分値を使用します。地点間では水位の基準面が異なるため、水位の絶対値ではなく各地点の増減や増水時刻を比較してください。水位だけで支流の流量や魚の活性を直接判定するものではありません。

### 増水の基準線

グラフの「増水基準」は直近3年の平均水位、赤線「大幅増水基準」は同期間の95パーセンタイル（上位約5％）です。紫色の水位帯は平均から95％点までを表示します。Aモードの判定も同じ期間の平均・90％点・95％点を使い、大幅増水基準以上は「かなり高い」と判定します。各地点の最新の有効な1時間観測時刻を終点とする3暦年分を集計し、欠測値と10分値は除外します。同時刻の10分値に上書きされた1時間値も、保存してある元の値を集計に戻します。3年未満の地点はその期間内の保有データで計算します。

表示期間の変更では基準線は変わりません。2016年からの履歴表示と「全期間の統計」は残し、Bモードは従来どおり直近7日平均との差を使います。基準線は統計的な目安であり、防災基準や釣行の安全基準ではありません。

計算・画面設定の回帰テスト: `node --test tests/test_reference_stats.cjs`。観測所設定（`config/stations.json`）のテスト: `python3 -m unittest discover -s tests -v`。
